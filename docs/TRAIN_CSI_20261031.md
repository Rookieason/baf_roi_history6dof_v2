# 20261031：使用已生成 CSI Heatmap 的訓練

目前 launcher 使用 [共同實驗入口](README_EXPERIMENTS.md)，預設跑 **BAF、Motion Transformer、HMD+CSI residual、Heatmap-assisted per-step alpha** 四個方法；可用 `--method` 選一個或多個。共同資料只準備一次，兩個 heatmap 方法使用同一份凍結 BAF，最後在相同 held-out origins 評估。

此 profile 讀取已生成的原始 Heatmap，不會在訓練時重算 MUSIC。舊 `python -m baf_roi_heatmap.recorded train` 仍保留為 residual-only 相容入口；新實驗建議使用共同 runner。

## 資料與設定

- 掃描 `db/20261031*/sensor.full.50010/*.csv`，解析 v2 canonical HMD；另外明確納入 `20260330-082303_record-5-minutes`。
- 新 session 使用 `hmd.50000` 的平面 cm / yaw-pitch-roll 欄位與 collector `recv_unix`；CSI 為 2025 subcarriers、5570 MHz。其餘場次維持原設定。此場沒有歷史 `run_params.json`，使用 config 明確設定並在每次 prepare 重算一張 Heatmap 比對，驗證失敗即停止。
- 原始位置為 cm；rotation 明確使用 yaw/pitch/roll，並與記錄的 quaternion 驗證一致。
- HMD capture 設定 30 Hz；實際接收間隔不均，因此沿用 30 幀 / 30 Hz 因果重採樣與 100 ms gap 分段。
- 使用 `intermediates/<session>/heatmaps/<session>_heatmaps.npz` 的 **AoA-ToF dB 數值**，不是 PNG 或 ToF-Doppler。
- radio 設定：1001 subcarriers、5775 MHz、天線順序 `[6,7,4,5,2,3,0,1]`；source grid 為 90×130，訓練用雙線性重採樣至 24×24。
- 每場串流讀取 25 個 CSI frame，抽查一張頻譜與 pinned valder 原碼數值一致；原始 Heatmap 不變。
- 載入時最多保留 30 map/s。CNN 使用最近 0.4 秒的 8 張圖；raw support 不超過 29/30 秒；staleness 上限 0.15 秒。
- 目前 config 的 horizons 為 50–1000 ms、每 50 ms 一個，共20個；兩個 heatmap adapters 預設20 epochs、batch64、seed42；Motion Transformer預設30 epochs。BAF沿用四階段10／8／12／20 epochs。只用validation選checkpoint。

18 場中排除 `20261031-084133_upperbody_part`：所有圖在計入跨網卡接收與插值依賴後均超出 raw-support 預算。
其餘 17 場加上新 session，**18 場固定切成 train 12 / valid 3 / test 3**。新 session 整場放入 train，既有 valid/test 不變；三組仍涵蓋 upperbody、lowerbody、longlong。
同一 session 的 gap segments 始終在同一 split，不能把重疊視窗隨機拆到不同組。
切分存於 `configs/splits_20261031.json`；只有訓練資料用於 normalization，test 不用來選參數。
新增資料後請建立新的 run/cache，不能用 `--prepared` 沿用舊資料集。新 session 的 HMD 接收時間範圍約 366.7 秒（9533 筆），不按名稱截成 300 秒；仍依原有 gap 與 history/future 規則選取可用視窗。這是跨錄製日期的訓練組合，不能宣稱 unseen-day 評估。

## 時間與結果的解讀

使用 recorder CSV 的 `recv_unix`，避免把 CSI 主機約差 34 秒的 `rx_system_ns` 直接對到 HMD。
每張圖的 support 包含全部網卡、缺包插值兩端、以及 centered-background 所用的後續封包；圖在最後一個必要輸入抵達前不可使用。
這是 **接收時鐘上的離線 replay**，available time 沒有加入實測 Heatmap 計算延遲，不代表已驗證的線上 latency。
現有 `run_params.json` 沒有記錄所有歷史參數；逐場抽樣數值比對補強相容性證據，並非逐張回溯驗證。

沿用先前設定的 8³/object bounding-cube ROI proxy、FoV 110°，不是伺服器 48³ 網格與 occlusion renderer 的完整重現。
RF 軸未做硬體校準，因此明確標記 exploratory；同一天的 subject 身分未知，只能解讀為 session holdout。

## 2026-11-21：相同結果的根因與修正

`run_20261118T164339Z` 的兩個 CSI checkpoint 都選中了 epoch 0，輸出層權重為零；每個方法的 141,520 筆評估列均為 `correction_applied=0`，所以與凍結 BAF 完全一致。兩個模型均執行了 20 個訓練 epochs；不是 RF 全部缺失或把同一份報表複製到不同方法。保留 epoch 0 是避免接受退步模型的機制，不能以刪除這個候選來製造 CSI 增益。

已確認並修正以下問題：

- **影像年齡低估。** centered background 需要中心 frame 之後的資料。原程式把 support 完成時間同時當成影像的量測時間；原始 CSV 核對顯示中心 CSI row 的接收完成時間通常早約 125–130 ms。新匯入的 NPZ 增加 `measurement_s`；`timing[...,0]` 改用中心資料的 age，`support_end_s` 與 `available_at_s` 仍負責限制可用性，不把尚未完成的圖提前使用。此時間仍是 collector 接收時間，不能聲稱硬體 capture clocks 已校準。舊 checkpoint 的線上推論保留舊 age 定義，新 checkpoint 明確記錄 `rf_age_basis`。
- **訓練目標與選模目標不一致。** 原 train split 的基準 loss 中，translation 約 0.3064、rotation 約 6.7905，乘權重後的 ROI loss 僅約 0.0419。對共享 pose 修正量求梯度，pose 與 ROI 梯度 cosine 約 -0.300，顯示兩種改善方向有衝突。新預設使用 soft IoU loss，對應 margin 0 的 hard IoU；原 `pose_roi` loss 可供重現。訓練目標一致不代表已證明 CSI 能改善 held-out recordings。
- **訓練成果與基準回退沒有明示。** 現在同時保存選用的 `adapter.pt`／`alpha.pt`、`best_trained.pt` 與 `last.pt`。`training.json`、評估報告與共同 summary 會明示 selected epoch、`baseline_retained`／`trained_correction_selected` 及實際 correction 比例。

Residual 的 `--heatmap-aggregation` 預設保留 origin 等權重，可用 `recording` 對照原始錄製檔等權重；本次 residual 實驗沒有顯示加權更好。Alpha 的 `--alpha-aggregation` 預設為本次驗證的 `recording`，兩者可分別設定。此處 recording ID 是 session 加來源 CSV hash，與 session 數、gap segment 數不同。全部 split、targets、BAF weights、scene 與 horizons 保持原實驗的定義。

原始 HMD sample serial 另經檢查：錄製到的取樣間隔中位數約 47–59 ms，取樣與接收間隔差的相對抖動 p99 約 34–76 ms；這不等於已估出絕對網路延遲。30 Hz 是重採樣契約，不能把插值後的 30 Hz 視窗當作完整、精確同步的 30 Hz 原始量測。上述資料限制與未校準的 RF physical axes 都仍存在，不應以任意平移 timestamps 的方式掩蓋。

CUDA alpha 訓練原本對整段 rollout 關閉 cuDNN，連 confidence／Explorer convolution 都受影響。現在僅為凍結 LSTM 啟用 backward reserve，RNN dropout 固定為 0，其餘 frozen expert 仍為 eval；呼叫後還原 flags。RTX 3070 上 16 筆、30-step 的 forward/backward 比對約由 2.47 s 降至 0.50 s，位置最大差約 0.118 mm、角度最大差約 0.0121°，gate gradient 最大差約 1.43e-5；這是 float32 backend 差異，並非 bit-exact 聲明。

原始資料檢查與不覆寫的時間修復指令：

```bash
python scripts/audit_csi_training.py --prepared <old-run>/prepared \
  --raw-root <sensor-agent-publish-subscribe> --output <new-diagnostics>/audit.json

python scripts/repair_csi_timing.py --prepared <old-run>/prepared \
  --raw-root <sensor-agent-publish-subscribe> --output <new-diagnostics>/prepared_center_timing
```

修復工具逐一驗證原始 matched CSV SHA-256、map 選取索引與 dependency bounds，複製原有 frozen supervision 後建立新 experiment ID。原始 maps、cache、模型與結果均不覆寫。**舊 `--prepared` 沿用舊的時間特徵；僅同步 Python 程式不會替既有 maps 補出中心時間。**

重現舊訓練目標可使用 `--heatmap-objective pose_roi --heatmap-aggregation origin --alpha-aggregation origin`。新預設為 `--heatmap-objective roi_iou --heatmap-aggregation origin --alpha-aggregation recording`。完整對照工具 `scripts/validate_csi_fix.py` 會把 train／valid 的相同輸入保留在 RAM，避免打散 origin 後反覆解壓整份 trajectory NPZ；仍沿用原資料集與 trainer，並受原有 RAM／RSS／disk guard 限制。沒有在 test 上選參數或 epoch。

`scripts/evaluate_csi_fix.py` 提供 validation 內、同 session 的 RF window permutation 負對照，固定 HMD、targets 與 RF-available cohort。若真實 RF 與打亂 RF 的結果相近，不能把相對 BAF 的改善都歸功於 CSI。修正版報告存於遠端輸出根目錄的 `diagnostics_20261121/`；更新前的程式另存為 `before_fix.tar` 與 `before_gpu_report.tar`。

最終固定權重的結果如下（margin 0，50–1000 ms 等權重平均；checkpoint 只以 validation recording-macro IoU 選擇）：

| 方法 | selected epoch | validation recording-macro IoU | test pooled IoU | test recording-macro IoU |
|---|---:|---:|---:|---:|
| BAF | — | 0.744099 | 0.703828 | 0.755448 |
| 修正版 residual：ROI loss、中心時間、origin 等權重 | 4 | 0.745272 | 0.703476 | 0.757276 |
| 修正版 alpha：ROI loss、中心時間、recording 等權重 | 15 | 0.747140 | 0.703978 | 0.757007 |

兩個修正版在 test 的 `correction_applied_fraction` 均為 1，已不再與 BAF 完全相同。Residual 的 test pooled 指標反而略低，不能宣稱兩個方法全面改善。Alpha 的 test pooled 差異只有約 +0.000150；以 3 個 held-out sessions 做配對 cluster bootstrap，探索性 95% 區間約 [-0.000396, +0.002820]，包含 0。

RF 負對照中，中心時間 residual 的 validation recording-macro IoU 為 0.745272，打亂後為 0.745449；alpha 為 0.747140，打亂後為 0.746779。現有模型對正確 RF 配對的依賴很弱，仍沒有穩健的 CSI 額外增益證據。修正 age 定義也不會消除 centered heatmap 本身的資料等待延遲。

`diagnostics_20261121/corrected_run/summary.csv` 是修正後四方法、全部 20 horizons 與 4 margins 的正式共同評估；`experiment.json` 記錄可重用的確切 checkpoints 和 hashes。原 BAF／Motion Transformer 權重沿用，兩個 adapter 各完成 20 epochs。額外的 alpha history 重用版本完整重現全部 20 輪 loss 與 validation scores，並記錄在 `history_cache_parity.json`。所有診斷對照、RF 負對照與跨場次不確定區間保存在同一診斷目錄；test 結果沒有用於後續調參。
